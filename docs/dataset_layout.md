# Dataset Layout

This package supports two layout levels:

1. Raw dataset layout: the folder structure expected by the original dataset file players.
2. Converted dataloader layout: the unified structure generated by `dataloader_convert.py`.

## Raw MulRan Layout

Select or pass one MulRan sequence directory as `--source`.

```text
<mulran_sequence>/
  sensor_data/
    data_stamp.csv
    gps.csv
    xsens_imu.csv
    Ouster/
      <timestamp_ns>.bin
    radar/
      polar/
        <timestamp_ns>.png
```

Required files:

- `sensor_data/data_stamp.csv`: timeline rows in `<timestamp_ns>,<sensor_name>` format.
- `sensor_data/Ouster/*.bin`: Ouster LiDAR scans. The original player reads `x, y, z, intensity` as float32 values and derives `ring`.
- `sensor_data/radar/polar/*.png`: Navtech radar polar images.
- `sensor_data/gps.csv`: GPS rows used for `/gps/fix`.
- `sensor_data/xsens_imu.csv`: Xsens IMU rows used for `/imu/data_raw` and optionally `/imu/mag`.

Known MulRan timeline sensor names:

- `ouster`
- `radar`
- `gps`
- `imu`

Some local MulRan sequences store radar as `sensor_data/radara/polar`; the converter accepts both `radar/polar` and `radara/polar`.

If a timeline contains `radar` but neither radar folder exists, the converter excludes radar from the converted manifest instead of failing.

## Raw HeLiPR Layout

Select or pass one HeLiPR sequence directory as `--source`.

```text
<helipr_sequence>/
  stamp.csv
  Inertial_data/
    inspva.csv
    xsens_imu.csv
  LiDAR/
    Ouster/
      <timestamp_ns>.bin
    Velodyne/
      <timestamp_ns>.bin
    Avia/
      <timestamp_ns>.bin
    Aeva/
      <timestamp_ns>.bin
```

Required files:

- `stamp.csv`: timeline rows in `<timestamp_ns>,<sensor_name>` format.
- `Inertial_data/inspva.csv`: NovAtel INS/GNSS rows used for `/inspva`.
- `Inertial_data/xsens_imu.csv`: Xsens IMU rows used for `/imu/data_raw` and optionally `/imu/mag`.
- `LiDAR/Ouster/*.bin`: Ouster scans.
- `LiDAR/Velodyne/*.bin`: Velodyne scans.
- `LiDAR/Avia/*.bin`: Livox Avia scans. Playback of this topic requires `livox_ros_driver`.
- `LiDAR/Aeva/*.bin`: Aeva scans.

Some local HeLiPR sequences use suffixed LiDAR folder names such as `Oustera`, `Velodynea`, `Aviaa`, or `Aevaa`; the converter accepts both the normal and suffixed names.

If a timeline contains a LiDAR label but the corresponding folder is absent, the converter excludes that sensor from the converted manifest instead of failing. This matches local sequences where, for example, `velodyne` labels exist but no Velodyne folder is present.

Known HeLiPR timeline sensor names:

- `inspva`
- `imu`
- `ouster`
- `velodyne`
- `livox_avia`
- `aeva`

## Converted Dataloader Layout

The converter writes one sequence to:

```text
<converted_root>/
  <dataset>/
    <sequence>/
      manifest.yaml
      timeline.csv
      sensors/
        lidar/
          <lidar_name>/
            <timestamp_ns>.bin
        imu/
          xsens_imu.csv
        gps/
          gps.csv
        inertial/
          inspva.csv
        radar/
          polar/
            <timestamp_ns>.png
```

`manifest.yaml` records the dataset name, sequence name, available sensors, default topics, frame IDs, and primary LiDAR. `timeline.csv` has normalized rows:

```text
timestamp_ns,sensor,relative_path
```

Large per-frame files are not re-encoded. By default the converter uses `reference` mode: it writes `manifest.yaml` and `timeline.csv`, and the timeline points to the original raw files by absolute path. This uses almost no extra disk space and works on external drives that do not support symlinks or hardlinks.

Other storage modes:

- `--link-mode symlink`: create a unified folder tree with symlinks.
- `--link-mode hardlink`: create a unified folder tree with hardlinks.
- `--link-mode hardlink_or_copy`: try hardlinks, then copy on failure.
- `--link-mode copy`: copy files into the converted tree.

## Convert Examples

```bash
rosrun dataloader dataloader_convert.py \
  --dataset mulran \
  --source /data/raw/MulRan/KAIST01 \
  --output /data/converted_datasets \
  --sequence KAIST01
```

```bash
rosrun dataloader dataloader_convert.py \
  --dataset helipr \
  --source /data/raw/HeLiPR/DCC01 \
  --output /data/converted_datasets \
  --sequence DCC01
```

Use `--link-mode copy` if the converted dataset must be independent from the raw dataset. For quick tests, convert only a LiDAR frame range:

```bash
rosrun dataloader dataloader_convert.py \
  --dataset helipr \
  --source /data/raw/HeLiPR/KAIST05 \
  --output /data/converted_datasets \
  --sequence KAIST05_test \
  --start-lidar-frame 0 \
  --end-lidar-frame 20
```

## Playback Examples

Edit `config/mulran.yaml` or `config/helipr.yaml`, then run:

```bash
roslaunch dataloader player.launch config:=$(rospack find dataloader)/config/mulran.yaml
```

For LiDAR frame slicing, set:

```yaml
start_lidar_frame: 100
end_lidar_frame: 200
```

The frame indices are 0-based. The player uses the selected primary LiDAR timestamps to define the playback time range, then publishes all enabled topics whose timestamps fall inside that range.
