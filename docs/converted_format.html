권장 사용 방식

일반적인 사용은 copy mode로 변환해서 converted folder만 남기는 방식입니다. 이렇게 저장하면 dataset 종류와 상관없이 manifest.yaml, timeline.csv, sensors/, poses/를 같은 규칙으로 읽을 수 있습니다.

self-contained기본 copy mode는 원본 없이도 재생 가능합니다.
batch ready여러 sequence를 순서대로 자동 변환합니다.
safe cleanup검증 통과 후 raw sequence 삭제가 가능합니다.
source /opt/ros/noetic/setup.zsh
source /home/beom/dynamic_ws/devel/setup.zsh

rosrun dataloader dataloader_convert.py \
  --dataset mulran \
  --source /media/beom/ux_dataset1/dataset/mulran/DCC01 \
  --output /media/beom/ux_dataset1/converted_dataset \
  --sequence DCC01
변환이 끝나면 console summary에서 status: OK, sensor별 event 수, 저장 위치, pose file 수를 확인합니다.

기본 copy mode에서는 sensor file까지 converted tree 안으로 복사합니다. 그래서 converted folder만 공유해도 player와 offline algorithm이 같은 timeline.csv, manifest.yaml, sensor file을 기준으로 읽을 수 있습니다.

manifest.yaml

dataset 이름, sequence 이름, 사용 가능한 sensor, 기본 topic, frame ID, primary LiDAR, pose file 위치를 기록합니다.

dataset: helipr
sequence: KAIST05
primary_lidar: ouster
timeline: timeline.csv
sensors:
  ouster:
    kind: pointcloud
    format: helipr_ouster
    topic: /ouster/points
    frame_id: ouster
  livox_avia:
    kind: livox_custom
    format: helipr_livox_avia
    topic: /avia/points
    frame_id: livox_avia
poses:
  gt:
    default: poses/gt_ouster.txt
    ouster: poses/gt_ouster.txt
    livox_avia: poses/gt_livox_avia.txt
  gt_global:
    default: poses/gt_global_ouster.txt
    ouster: poses/gt_global_ouster.txt

timeline.csv

모든 dataset은 아래 공통 형식으로 정렬됩니다.

timestamp_ns,sensor,relative_path
1690000000000000000,ouster,sensors/lidar/ouster/1690000000000000000.bin
1690000000010000000,imu,sensors/imu/xsens_imu.csv

player는 primary_lidar의 frame index로 시간 구간을 정한 뒤, 그 시간 범위 안에 들어오는 enabled sensor event만 publish합니다.

timestamp는 seconds 또는 nanoseconds를 허용합니다. converter가 저장하는 값은 nanoseconds 기준입니다.

Storage Mode

Mode동작권장 상황
copysensor file을 모두 복사합니다.기본값, 원본 삭제/공유 가능
referencemetadata만 저장하고 원본 file absolute path를 참조합니다.빠른 local test, 용량 최소화
symlink통일된 폴더 구조에 symlink를 만듭니다.filesystem이 symlink를 지원할 때
hardlinkhardlink를 생성합니다.같은 filesystem 안에서 중복 저장을 피할 때
hardlink_or_copyhardlink 실패 시 copy합니다.portable한 결과물이 필요할 때
원본 dataset을 지울 계획이면 copy mode를 사용해야 합니다. reference, symlink, hardlink는 원본 또는 filesystem 상태에 의존할 수 있으므로 공유/삭제용 결과물로 쓰지 않습니다.

Convert 명령어

rosrun dataloader dataloader_convert.py \
  --dataset mulran \
  --source /media/beom/ux_dataset1/dataset/mulran/KAIST01 \
  --output /media/beom/ux_dataset1/dataset/converted \
  --sequence KAIST01
rosrun dataloader dataloader_convert.py \
  --dataset helipr \
  --source /media/beom/ux_dataset1/dataset/helipr/KAIST05 \
  --output /media/beom/ux_dataset1/dataset/converted \
  --sequence KAIST05 \
  --start-lidar-frame 100 \
  --end-lidar-frame 200
rosrun dataloader dataloader_convert.py \
  --dataset semantic_kitti \
  --source /media/beom/T71/dataset/semantic_kitti/00 \
  --output /media/beom/T71/dataset/converted \
  --sequence 00

여러 sequence를 자동 변환할 때는 batch script를 사용할 수 있습니다. 이미 변환된 sequence는 기본으로 건너뜁니다.

rosrun dataloader convert_sequences.sh \
  --dataset helipr \
  --source-root /media/beom/ux_dataset1/dataset/helipr \
  --output /media/beom/ux_dataset1/converted_dataset
Option설명
--overwrite이미 변환된 sequence를 삭제하고 다시 변환합니다.
--continue-on-error한 sequence가 실패해도 다음 sequence를 계속 변환합니다.
--link-mode referencesensor file을 복사하지 않고 원본 absolute path만 기록합니다. 빠른 local test용입니다.
--start-lidar-frame, --end-lidar-frame모든 sequence에 같은 LiDAR frame index 구간을 적용합니다.

용량 때문에 변환 직후 원본 sequence를 지우고 싶으면 아래 옵션을 사용합니다. 변환이 성공하고, storage_mode: copy이며, missing_files.txt가 없고, timeline.csv의 모든 파일이 converted folder 안에 실제로 존재할 때만 원본 sequence 폴더를 삭제합니다.

rosrun dataloader convert_sequences.sh \
  --dataset helipr \
  --source-root /media/beom/ux_dataset1/dataset/helipr \
  --output /media/beom/ux_dataset1/converted_dataset \
  --delete-source-after-success
--delete-source-after-success는 새로 변환에 성공한 sequence에만 적용됩니다. 이미 변환되어 skip된 sequence는 삭제하지 않습니다. 삭제 대상도 --source-root 아래의 sequence 폴더인지 확인한 뒤 삭제합니다.
