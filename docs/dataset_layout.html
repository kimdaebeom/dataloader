dataloader 데이터셋 구조

MulRan, HeLiPR 원본 폴더 구성, 변환된 dataset 구조, storage mode, playback 설정을 정리한 문서입니다.

개요 MulRan 원본 구조 HeLiPR 원본 구조 변환 후 구조 명령어 재생 Pose Transform

개요

이 패키지는 두 가지 데이터 구조를 다룹니다.

  1. Raw dataset layout: 기존 dataset file player가 기대하는 원본 폴더 구조입니다.
  2. Converted dataloader layout: dataloader_convert.py가 만드는 통일된 구조입니다.
기본 converter mode는 reference입니다. 실제 sensor file을 복사하지 않고 metadata와 원본 파일 absolute path만 저장하므로, symlink나 hardlink를 지원하지 않는 외장 드라이브에서도 용량을 거의 쓰지 않습니다.

MulRan 원본 구조

MulRan sequence 폴더 하나를 --source로 넘깁니다.

<mulran_sequence>/
  sensor_data/
    data_stamp.csv
    gps.csv
    xsens_imu.csv
    Ouster/
      <timestamp_ns>.bin
    radar/
      polar/
        <timestamp_ns>.png

필요한 파일

Path 용도
sensor_data/data_stamp.csv <timestamp_ns>,<sensor_name> 형식의 timeline입니다.
sensor_data/Ouster/*.bin Ouster LiDAR scan입니다. 기존 player는 x, y, z, intensity를 float32로 읽고 ring을 계산해서 넣습니다.
sensor_data/radar/polar/*.png Navtech radar polar image입니다.
sensor_data/gps.csv /gps/fix publish에 사용하는 GPS row입니다.
sensor_data/xsens_imu.csv /imu/data_raw publish에 사용하는 Xsens IMU row입니다. 설정에 따라 /imu/mag도 publish할 수 있습니다.

지원하는 Timeline Label

  • ouster
  • radar
  • gps
  • imu
일부 local MulRan sequence는 radar가 sensor_data/radara/polar에 저장되어 있습니다. converter는 radar/polar와 radara/polar를 모두 허용합니다.
timeline에 radar label이 있어도 실제 radar 폴더가 없으면 실패하지 않고 converted manifest에서 radar sensor를 제외합니다.

HeLiPR 원본 구조

HeLiPR sequence 폴더 하나를 --source로 넘깁니다.

<helipr_sequence>/
  stamp.csv
  Inertial_data/
    inspva.csv
    xsens_imu.csv
  LiDAR/
    Ouster/
      <timestamp_ns>.bin
    Velodyne/
      <timestamp_ns>.bin
    Avia/
      <timestamp_ns>.bin
    Aeva/
      <timestamp_ns>.bin

필요한 파일

Path 용도
stamp.csv <timestamp_ns>,<sensor_name> 형식의 timeline입니다.
Inertial_data/inspva.csv /inspva publish에 사용하는 NovAtel INS/GNSS row입니다.
Inertial_data/xsens_imu.csv /imu/data_raw publish에 사용하는 Xsens IMU row입니다. 설정에 따라 /imu/mag도 publish할 수 있습니다.
LiDAR/Ouster/*.bin Ouster scan입니다.
LiDAR/Velodyne/*.bin Velodyne scan입니다.
LiDAR/Avia/*.bin Livox Avia scan입니다. 이 topic을 playback하려면 livox_ros_driver가 필요합니다.
LiDAR/Aeva/*.bin Aeva scan입니다.

지원하는 Timeline Label

  • inspva
  • imu
  • ouster
  • velodyne
  • livox_avia
  • aeva
일부 local HeLiPR sequence는 Oustera, Velodynea, Aviaa, Aevaa처럼 뒤에 a가 붙은 LiDAR 폴더명을 사용합니다. converter는 일반 폴더명과 suffixed 폴더명을 모두 허용합니다.
livox_avia를 재생하려면 /home/beom/livox_ws/devel/setup.zsh 또는 setup.bash를 source해서 livox_ros_driver message가 ROS 환경에 잡혀 있어야 합니다.
timeline에 LiDAR label이 있어도 해당 sensor 폴더가 없으면 실패하지 않고 converted manifest에서 그 sensor를 제외합니다.

변환 후 Dataloader 구조

<converted_root>/
  <dataset>/
    <sequence>/
      manifest.yaml
      timeline.csv
      sensors/
        lidar/
          <lidar_name>/
            <timestamp_ns>.bin
        imu/
          xsens_imu.csv
        gps/
          gps.csv
        inertial/
          inspva.csv
        radar/
          polar/
            <timestamp_ns>.png

manifest.yaml에는 dataset 이름, sequence 이름, 사용 가능한 sensor, 기본 topic, frame ID, primary LiDAR 정보가 저장됩니다. timeline.csv는 아래 형식으로 정규화됩니다.

timestamp_ns,sensor,relative_path

원본 dataset에 GT pose가 있으면 converter가 TUM format으로 변환해서 poses/ 아래에 저장하고, manifest.yaml의 poses.gt에 기록합니다.

Storage Mode

Mode 동작
reference 기본값입니다. metadata만 저장하고 원본 파일 absolute path를 기록합니다.
symlink 통일된 폴더 구조를 만들고 symlink를 생성합니다.
hardlink 통일된 폴더 구조를 만들고 hardlink를 생성합니다.
hardlink_or_copy 먼저 hardlink를 시도하고, 실패하면 copy합니다.
copy 파일을 converted tree 안으로 복사합니다.

명령어

MulRan 변환

rosrun dataloader dataloader_convert.py \
  --dataset mulran \
  --source /data/raw/MulRan/KAIST01 \
  --output /data/converted_datasets \
  --sequence KAIST01

HeLiPR 변환

rosrun dataloader dataloader_convert.py \
  --dataset helipr \
  --source /data/raw/HeLiPR/DCC01 \
  --output /data/converted_datasets \
  --sequence DCC01

빠른 테스트용 Partial Conversion

rosrun dataloader dataloader_convert.py \
  --dataset helipr \
  --source /data/raw/HeLiPR/KAIST05 \
  --output /data/converted_datasets \
  --sequence KAIST05_test \
  --start-lidar-frame 0 \
  --end-lidar-frame 20

재생

config/mulran.yaml 또는 config/helipr.yaml을 수정한 뒤 실행합니다.

source /opt/ros/noetic/setup.zsh
source /home/beom/livox_ws/devel/setup.zsh      # livox_avia를 켤 때 필요
source /home/beom/dynamic_ws/devel/setup.zsh

roslaunch dataloader player.launch config:=$(rospack find dataloader)/config/helipr.yaml

MulRan만 재생하거나 HeLiPR에서 livox_avia: false를 유지한다면 livox_ws source는 필요하지 않습니다.

roslaunch dataloader player.launch config:=$(rospack find dataloader)/config/mulran.yaml

LiDAR Frame 구간 선택

start_lidar_frame: 100
end_lidar_frame: 200

frame index는 0-based입니다. player는 선택한 primary LiDAR timestamp로 playback 시간 구간을 정하고, 그 구간 안에 들어오는 enabled topic만 publish합니다.

Pose 기반 Transform 재생

SLAM 또는 GT pose를 이미 가지고 있는 실험에서는 playback 단계에서 LiDAR point cloud를 pose 기준 frame으로 변환해서 publish할 수 있습니다. pose는 TUM format을 사용합니다.

TUM Pose Format

timestamp tx ty tz qx qy qz qw

timestamp는 seconds 또는 nanoseconds 모두 허용합니다. player는 sensor timestamp와 가장 가까운 pose를 찾고, 기본 50ms 이내일 때만 매칭합니다.

추가 4x4 Matrix

서로 다른 sequence에서 만든 submap을 같은 장소 기준으로 맞출 때는 추가 4x4 matrix를 적용할 수 있습니다. txt 파일에는 숫자 16개를 저장합니다.

r00 r01 r02 tx
r10 r11 r12 ty
r20 r21 r22 tz
0   0   0   1

기본 적용 순서는 아래와 같습니다.

T_publish = T_static * T_pose
p_publish = T_publish * p_lidar

T_pose는 TUM pose에서 읽은 pose이고, T_static은 static_matrix_file에서 읽은 추가 submap 정합 matrix입니다.

static_transform_order: before_pose로 설정하면 T_publish = T_pose * T_static 순서로 적용합니다. LiDAR-to-body extrinsic처럼 pose 앞단에 붙일 transform이 필요할 때 사용합니다.

Config Example

transform:
  enabled: true
  pose_source: custom
  pose_file: /path/to/poses.tum
  pose_format: tum
  pose_timestamp_tolerance_ns: 50000000
  static_matrix_file: /path/to/submap_transform.txt
  static_transform_order: after_pose
  apply_to_pointcloud: true
  output_frame_id: map
  publish_pose: true
  pose_topic: /dataloader/pose

GT Pose 사용

converted dataset에 GT pose가 기록되어 있으면 직접 파일 경로를 쓰지 않고 pose_source: gt로 선택할 수 있습니다.

transform:
  enabled: true
  pose_source: gt
  pose_file: ""
  pose_format: tum
  apply_to_pointcloud: true
  output_frame_id: map
  publish_pose: true

MulRan은 global_pose.csv를 poses/gt.tum으로 변환합니다. HeLiPR은 LiDAR_GT/Ouster_gt.txt, Velodyne_gt.txt, Avia_gt.txt, Aeva_gt.txt를 LiDAR별 TUM pose로 저장하고, global_* GT도 gt_global pose로 함께 저장합니다.

pose_source: gt_global을 사용하면 manifest에 기록된 global GT pose를 자동 선택합니다.

transform.enabled: false이면 기존처럼 raw LiDAR frame으로 publish합니다. SLAM을 직접 돌리는 경우에는 이 설정을 끄는 것이 일반적입니다.
apply_to_pointcloud: true이면 ouster, velodyne, aeva, livox_avia point의 x,y,z에 transform을 적용합니다. image, GPS, IMU 값은 변환하지 않습니다.
